# Политика безопасности

Сундук специально рассчитан на работу в недоверенной сети: панель ограничена
локальной сетью, публичный порт отдаёт только страницы ссылок, а контейнер
запущен с `read-only` rootfs и `cap_drop: ALL`. Поэтому сообщения о проблемах
безопасности особенно важны.

## Как сообщить

Пожалуйста, **не создавайте публичный issue** для уязвимостей. Используйте
приватный канал GitHub:

**Security → Report a vulnerability** —
https://github.com/afanagr/sunduk/security/advisories/new

Укажите:

* версию (тег релиза или образ `ghcr.io/afanagr/sunduk` с digest);
* как воспроизвести (запрос, настройки `config/config.yml`, при необходимости);
* предполагаемое влияние: обход ограничения сетей, выход за пределы
  подключённого каталога, обход пароля/лимитов ссылки, повышение прав внутри
  контейнера и т. п.

## Что уже учтено

Перед отчётом полезно свериться с разделом «Безопасность» в
[README.md](README.md):

* панель отвечает только сетям из `lan_allowlist`, вход по scrypt-паролю,
  подписанная сессия и CSRF-токен на изменения;
* публичный порт отдаёт только страницы ссылок, с лимитом запросов на IP;
* пути нормализуются и проверяются на принадлежность корню каталога —
  `..` и симлинки наружу не проходят;
* активный контент (HTML, SVG, JS, XML, JSON) отдаётся как
  `application/octet-stream`, включены CSP и `X-Content-Type-Options: nosniff`;
* контейнер: root нужен для работы с чужими файлами, но добавлены ровно три
  capability (`CHOWN`, `DAC_OVERRIDE`, `FOWNER`), включены `no-new-privileges`
  и tmpfs 64 МБ для `/tmp`.

## Поддерживаемые версии

Исправления выходят для последнего релиза. Рекомендуется держать образ
`ghcr.io/afanagr/sunduk` на актуальном теге.
