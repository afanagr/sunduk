# Сундук (Sunduk)

Self-hosted веб-файловый менеджер в Docker: управление файлами на сервере из
локальной сети и **публичные ссылки на файлы и папки** для доступа из интернета.

Две независимые поверхности:

* **панель** — порт `8080`, только локальная сеть, вход по паролю;
* **внешние ссылки** — порт `8081`, отдаёт исключительно страницы ссылок.

Установка не требует правки `docker-compose.yml` и переменных окружения:
**все каталоги подключаются прямо в панели** — вы указываете путь к папке на
сервере (`/mnt/media`) и имя, под которым она будет видна в интерфейсе.

---

## Возможности

| Раздел | Что умеет |
|--------|-----------|
| Первый запуск | встроенная учётная запись `admin` / `admin`, панель требует сменить пароль сразу после входа |
| Каталоги | подключение любого каталога сервера из панели: путь + имя, встроенный проводник по папкам сервера, опция «создать, если нет»; переименование и отключение без правки конфигов |
| Файловые операции | полный доступ всегда: список, загрузка (в т.ч. drag & drop), создание папок, переименование, перемещение и копирование между каталогами, удаление, поиск — без режимов «только чтение» |
| Просмотр медиа | полноэкранный просмотрщик с навигацией ‹/›: изображения, видео (mp4/mkv/webm/mov…), аудио, PDF и текст; плиточный режим с миниатюрами |
| Видео онлайн | видео и аудио стримятся с поддержкой HTTP Range (206) — перемотка без скачивания файла |
| Внешние ссылки | токен, срок действия, пароль (виден администратору), лимит скачиваний, счётчик скачиваний, отзыв; широкое окно управления со сводкой и фильтром |
| Публичная страница | просмотр папки (навигация, список/плитка) или файла, разблокировка по паролю, скачивание |
| Мобильные устройства | выезжающее меню, карточки вместо таблиц, полноэкранный просмотрщик |
| Безопасность | LAN-allowlist, защита от обхода каталогов, rate limiting, CSP/nosniff, read-only rootfs, `cap_drop: ALL` + три нужные capability |

---

## Требования

* Linux-сервер с Docker Engine и Compose v2 (`docker compose version`).
* Свободные порты `8080` (панель, локальная сеть) и `8081` (внешние ссылки).
* Каталоги сервера подключаются напрямую, поэтому `docker-compose.yml` монтирует
  `/` в `/host`, а `docker compose` нужно запускать от root.

## Быстрый старт

```bash
git clone <repo> && cd sunduk
docker compose up -d --build
```

1. Откройте панель: `http://<адрес-сервера>:8080` → вход **admin / admin**.
2. Панель сразу попросит задать новый пароль — это обязательный шаг.
3. Нажмите **«＋ Добавить каталог»** в сайдбаре и укажите каталог на сервере.
4. Готово: файлы доступны. Для доступа из интернета используйте порт `8081`.

Никакие `.env` не нужны: Сундук не читает переменные окружения вообще.
Все настройки лежат в одном файле `config/config.yml`.

## Как подключить каталог

Панель работает с файловой системой сервера напрямую: `docker-compose.yml`
монтирует её как `/:/host`, а вы задаёте привычные пути сервера.

1. **＋ Добавить каталог**
2. **Путь на сервере** — например `/mnt/media`, `/srv/photos` или `/home/user/docs`.
   Кнопка **📁 Выбрать на сервере** открывает проводник: можно пройти по папкам
   сервера и выбрать нужную (быстрые ссылки на `/`, `/mnt`, `/srv`, `/media`,
   `/storage`, `/home`, `/opt`, `/var/lib`).
3. **Имя в панели** — то, что видно в сайдбаре. Можно оставить пустым, тогда
   подставится имя папки.
4. При необходимости поставьте галочку **«Создать каталог, если его ещё нет»**.

Ограничения и особенности:

* путь должен быть абсолютным; `..` и относительные пути отклоняются;
* путь ищется внутри того, что смонтировано в `host_root` (`/host`) — иначе
  каталог добавить нельзя (это защита от выхода за пределы монтирования);
* если каталог позже пропал (отмонтировали диск), он помечается «каталог
  недоступен» и его можно поправить или убрать;
* **«Убрать из панели»** удаляет только запись из панели: файлы на сервере
  остаются нетронутыми, а внешние ссылки этого каталога отзываются.

### Ограничение доступа к файловой системе

По умолчанию смонтирован весь сервер (`/:/host:rw`). Хотите ограничить —
замените в `docker-compose.yml` эту строку на список нужных каталогов:

```yaml
    volumes:
      - /mnt/media:/host/mnt/media:rw
      - /srv/data:/host/srv/data:rw
      - ./config:/config:ro
      - sunduk_data:/data
```

После этого в панели будут доступны только `/mnt/media` и `/srv/data`.

> Проверить интерфейс без подготовки файлов можно на папке `demo-data/media`
> из этого репозитория: скопируйте её на сервер и укажите в панели путь к ней
> (например `/opt/sunduk/demo-data/media`).

## Как выдать ссылку

1. В панели нажмите 🔗 в строке файла или папки (либо откройте раздел
   **«Внешние ссылки»** в сайдбаре).
2. Укажите срок действия, при необходимости пароль и лимит скачиваний.
3. Скопируйте готовый URL вида `http://<сервер>:8081/s/<token>` — он работает
   без авторизации.

Окно «Внешние ссылки» — центр управления: сводка (всего / активных /
скачиваний), фильтр по объекту, ссылке или каталогу и таблица с колонками
«объект», «ссылка» (копировать/открыть), «статус» (`активна`, `истекла`,
`отозвана`, `лимит исчерпан`), «пароль» (показать/скопировать, виден только
администратору), «скачиваний» и «истекает» (дата и сколько осталось).
Кнопка **⛔ Отозвать все** убивает все активные ссылки сразу.

Пароль ссылки хранится в базе дважды: необратимым scrypt-хешем (для проверки) и
зашифрованной копией, чтобы администратор мог посмотреть его повторно.
Шифрование опирается на секретный ключ из `/data/secret.key`.

## Конфигурация

Единственный файл настроек — `config/config.yml` (монтируется в контейнер как
`/config/config.yml` read-only). После правки: `docker compose restart`.

| Секция | Ключи |
|--------|-------|
| Слушатели | `host`, `admin_port`, `public_port`, `base_url` |
| Пути | `data_dir`, `host_root`, `secret_key` |
| Доступ | `lan_allowlist` (CIDR, кому отвечает панель), `trusted_proxies` |
| Безопасность | `max_upload_mb`, `session_max_age_hours`, `cookie_secure`, `cookie_name`, `csrf_enabled`, `login_rate_limit_per_minute`, `public_rate_limit_per_minute`, `max_preview_mb` |
| Ссылки | `default_expiry_hours`, `max_expiry_hours`, `default_max_downloads` |

Что важно знать:

* **`base_url`** — адрес, из которого строятся ссылки. Обязан указывать на
  публичный порт (`8081`), иначе получатели получат нерабочий URL. Если он
  начинается с `https://`, cookie сессии автоматически становятся `Secure`.
* **`host_root`** — префикс, под которым файловая система сервера видна в
  контейнере (`/host`). Меняйте вместе с точкой монтирования в
  `docker-compose.yml`.
* **`secret_key`** — можно оставить пустым: Сундук создаст
  `/data/secret.key` при первом запуске и будет переиспользовать его. Значение
  из файла имеет приоритет (нужно только для переноса на другой сервер).
* **`lan_allowlist`** — панель отвечает только этим сетям. Доступ через VPN
  или другую подсеть добавляется сюда.
* Каталоги и пароль администратора **не** живут в этом файле: первые хранятся
  в базе (`/data/sunduk.db`), второй меняется в панели.

## Боевое развёртывание

Каталог `deploy/` — готовый комплект: compose-файл с фиксированными портами,
боевой `config/config.yml`, `install.sh` и инструкция `deploy/README.md`.
Собирается из `server/` этого же репозитория (клонируйте его целиком) либо из
готового образа `sunduk-*.tar`:

```bash
cd deploy
docker compose up -d --build          # или: docker load < sunduk-1.0.0.tar
```

Чек-лист:

1. В `config/config.yml` укажите `base_url` (например
   `https://files.example.com`) и, при необходимости, свою подсеть в
   `lan_allowlist`.
2. Порт **8080 не пробрасывайте** на роутере — он для локальной сети.
3. Порт **8081** (или HTTPS-прокси перед ним) открывайте наружу.
4. Первый вход: `admin / admin` → панель попросит новый пароль.
5. Добавьте каталоги в панели.

### HTTPS

Публичный порт лучше спрятать за reverse-proxy (Caddy, nginx, Traefik):

```caddy
files.example.com {
    reverse_proxy 127.0.0.1:8081
}
```

Затем в `config/config.yml` поставьте `base_url: "https://files.example.com"` и
`trusted_proxies: ["172.16.0.0/12"]` (сеть прокси), если он передаёт
`X-Forwarded-For`. `cookie_secure` включится сам из-за `https://` в `base_url`.

### Обновление с предыдущей версии

Версия с `.env` и каталогами в `config/config.yml` больше не поддерживается:
файла `.env` нет, разделы `users`/`shares` игнорируются (в логах появится
предупреждение). После обновления зайдите в панель, задайте пароль и заново
добавьте каталоги — это две минуты. Ссылки, созданные до обновления, останутся
в базе, но будут привязаны к старым идентификаторам каталогов и перестанут
работать: создайте их заново.

```
    ├── Dockerfile           # python:3.12-slim

    ├── run.py               # два сервера в двух процессах + супервизор
    ├── tools/
    │   ├── smoke_test.py    # сквозной E2E-тест (админка + публичный порт)
    │   └── reset_admin.py   # сброс пароля администратора
    └── app/
        ├── admin_app.py     # LAN-API: файлы, каталоги, ссылки, пароль
        ├── public_app.py    # публичный API: только ссылки
        ├── directories.py   # подключённые каталоги сервера (база + проводник)
        ├── users.py         # учётные записи (scrypt, смена при первом входе)
        ├── auth.py          # сессии, CSRF, принудительная смена пароля
        ├── config.py        # модель и загрузчик config/config.yml
        ├── storage.py       # операции с файлами (path confinement)
        ├── shares.py        # сервис внешних ссылок
        ├── db.py            # SQLite (users, directories, share_links)
        ├── crypto.py        # шифрование токенов и паролей ссылок
        ├── security.py      # scrypt, пути, CIDR, rate limit
        ├── common.py        # middleware, отдача файлов (inline/range/типы)
        └── static/          # index.html/app.js/styles.css + share.html/share.js
```

## Безопасность

* **Панель** — только для сетей из `lan_allowlist`; вход по scrypt-паролю,
  подписанная cookie-сессия и `X-CSRF-Token` на каждое изменение.
  Пока действует пароль `admin`, любые вызовы API кроме смены пароля
  отдают `428` — так исключается работа «по умолчанию».
* **Публичный порт** отдаёт только `/s/{token}`, `/api/share/{token}` и его
  `unlock`/`download`/`raw` плюс статику; лимит запросов на IP и отдельный
  лимитер на подбор пароля ссылки.
* **Токены ссылок** хранятся хешем SHA-256, для повторного показа админу —
  зашифрованной копией (Fernet на ключ из `/data/secret.key`).
* **Пути** нормализуются (`realpath`) и проверяются на принадлежность корню
  каталога: `..` и симлинки наружу не проходят ни в панели, ни по ссылке.
* **Активный контент** (HTML, SVG, JS, XML, JSON) всегда скачивается как
  `application/octet-stream`; CSP и `X-Content-Type-Options: nosniff` включены
  глобально. Единственное исключение — PDF, которому разрешено встраивание
  только своим источником (`frame-ancestors 'self'`), иначе просмотрщик не
  работает.
* **Контейнер**: контейнер запущен от root (он управляет каталогами сервера,
  владельцы которых могут быть любыми), но всё остальное закрыто —
  read-only rootfs, `no-new-privileges`, tmpfs 64 МБ для `/tmp` и
  `cap_drop: ALL`. Обратно добавлены ровно три capability, без которых работа с
  чужими файлами невозможна: `CHOWN`, `DAC_OVERRIDE` (запись в каталог,
  принадлежащий другому пользователю — обычная ситуация для `/mnt/media`) и
  `FOWNER`. Единственные writable-точки — `/data` и смонтированные каталоги.
  Загрузки буферизуются в `/data/tmp`, поэтому `/tmp` не может переполниться
  при большом файле.

## Обслуживание

```bash
docker compose logs -f                      # логи обоих серверов
docker compose restart                      # применить config/config.yml
docker compose down                         # остановить
docker compose down -v                      # + удалить базу, ключ и ссылки

# пароль администратора потерян -> сбросить и сменить при следующем входе
docker compose exec sunduk python tools/reset_admin.py
docker compose exec sunduk python tools/reset_admin.py 'новый-пароль'

# сквозная проверка работоспособности (внутри контейнера)
docker compose exec -T sunduk python tools/smoke_test.py
docker compose exec -T sunduk python tools/smoke_test.py --password 'мой-пароль'
docker compose exec -T sunduk python tools/smoke_test.py --big-mb 96
```

Бэкап — это два файла в томе `sunduk_data`: `sunduk.db` (каталоги,
пользователи, ссылки) и `secret.key` (без него зашифрованные токены ссылок не
прочитать).

### Что проверяет smoke test

Тест поднимает собственные каталоги в `/tmp/sunduk-smoke` (на сервере),
подключает их через API панели, прогоняет весь функционал и всё за собой
убирает: вход и CSRF, принудительную смену пароля по умолчанию (включая
`428`-запрет и возврат исходного пароля), добавление/переименование/удаление
каталогов и все проверки путей, проводник по папкам сервера, списки, поиск,
полный цикл записи (mkdir, upload, rename, move, copy, delete), защиту от
обхода каталогов, предпросмотр медиа (`video/mp4`, `video/x-matroska`, PDF с
разрешённым фреймом, HTML как download), HTTP Range (206), внешние ссылки
(файл, папка, пароль, лимит, показ пароля админу), публичную страницу
(метаданные, download, raw, unlock, диапазоны), отзыв ссылок и выход.
Флаг `--big-mb N` добавляет проверку загрузки файла размером N МБ.

## Диагностика

| Симптом | Причина / решение |
|---------|-------------------|
| `403 Доступ разрешён только из локальной сети` | IP вне `lan_allowlist` — добавьте подсеть или заходите через LAN/VPN |
| Панель требует новый пароль и ничего не открывается | это защита от работы с паролем `admin`: задайте свой (сброс — `tools/reset_admin.py`) |
| «Каталог недоступен на сервере: /…» | каталог отмонтировали или переименовали; поправьте путь в панели |
| «каталог не найден на сервере» при добавлении | путь не существует или лежит вне `host_root`; включите галочку «Создать каталог» или проверьте монтирование |
| В логах `host_root /host is missing` | в `docker-compose.yml` нет строки `- /:/host:rw` |
| В логах `data directory /data is unusable: no write permission` | том `/data` остался от старой версии и принадлежит другому пользователю: `docker run --rm -v sunduk_data:/data alpine chown 0:0 /data` (или верните capability `DAC_OVERRIDE`) |
| Изменения в файлах не видны | обновите список (⟳) — содержимое читается на каждый запрос |
| Ссылка «не найдена» | истёк срок, исчерпан лимит скачиваний, ссылка отозвана или каталог убран из панели |
| Загрузка крупного файла обрывается (`Connection reset`) | в логах `No space left on device`: проверьте место на томе `/data` (для буферизации загрузок `/tmp` не используется) |
| Публичный порт недоступен извне | пробросьте `8081` на роутере и укажите внешний адрес в `base_url` |
| `docker compose` не даёт смонтировать `/` | запускайте compose от root (`sudo`) — монтаж корня сервера требует прав |
