# Сундук — боевое развёртывание

Готовый комплект для сервера: образ собирается из `../server`, настройки лежат в
`./config/config.yml` (или задаются переменными окружения), каталоги
подключаются прямо в панели.

```
deploy/
├── docker-compose.yml     # панель 8080 (LAN) + ссылки 8081 (наружу)
├── config/config.yml      # настройки (или переменные окружения)
└── install.sh             # сборка (или docker load) и запуск
```

Сборка идёт из каталога `../server`: исходники приложения лежат в этом же
репозитории и в `deploy/` не дублируются, поэтому клонируйте репозиторий целиком.

Если сервером управляет панель стеков (Dockge, Portainer), есть минимальный
файл [`docker-compose.dockge.yml`](docker-compose.dockge.yml): `config/config.yml` рядом
не нужен и том не нужен — настройка целиком в трёх переменных окружения внутри файла
(`admin_port`, `public_port` и `public_address` — IP, домен или `https://домен` для
HTTPS-прокси), остальное берётся из значений по умолчанию. Сеть — `network_mode: host`:
контейнер слушает порты прямо на сервере, поэтому на роутере открывается только
`public_port`.

## Установка

```bash
sudo ./install.sh                 # или вручную:
sudo docker compose up -d --build
```

Если в каталоге лежит `sunduk-*.tar` (готовый образ с машины сборки),
`install.sh` сначала сделает `docker load` — тогда ни исходников, ни интернета,
ни сборки на сервере не потребуется.

## Первые шаги

1. **Панель:** `http://<ip-сервера>:8080` → вход `admin / admin`.
   Панель сразу потребует задать новый пароль — без этого она закрыта.
2. **Каталоги:** кнопка «＋ Добавить каталог» → путь на сервере (например
   `/mnt/media`) и имя для панели. Проводник «📁 Выбрать на сервере» поможет
   найти нужную папку, галочка «Создать каталог» создаст её при необходимости.
3. **Загрузка:** кнопка **⬆ Загрузить** — файлы, кнопка **🗂 Папку** — каталог
   целиком (структура вложенных папок воспроизводится на сервере). Файлы и папки
   можно просто перетащить в окно, а брошенные **на папку в списке** попадут
   внутрь неё.
4. **Ссылки:** кнопка 🔗 у файла/папки; раздел «Внешние ссылки» — управление
   всеми ссылками (статус, пароль, лимит скачиваний, отзыв).
5. **Папка архивом:** на странице ссылки кнопка **🗜 Архив** отдаёт папку одним
   ZIP-файлом (архив собирается на лету, место на диске не расходуется).

## Сеть и порты

| Порт | Назначение | Наружу |
|------|-----------|--------|
| 8080 | панель (локальная сеть, вход по паролю) | **нет** |
| 8081 | страницы внешних ссылок | да (или через HTTPS-прокси) |

В `config/config.yml` (любое из этих значений можно задать переменной окружения —
`PUBLIC_ADDRESS`, `PUBLIC_PORT`, `LAN_ALLOWLIST`, `ADMIN_PORT`; подробности — в
разделе «Конфигурация» [общего README](../README.md)):

* `public_ip` — IP (или имя хоста), по которому доступен порт 8081: ссылки
  строятся как `http://<public_ip>:<public_port>`, например `95.31.37.196`;
* `base_url` — полный адрес ссылок; применяется, когда `public_ip` пуст (для
  HTTPS/домена): `https://files.example.com`.
* `lan_allowlist` — кому отвечает панель. Оставьте свои подсети (VPN, другой
  сегмент сети — добавьте сюда).

### HTTPS за reverse-proxy

```caddy
files.example.com {
    reverse_proxy 127.0.0.1:8081
}
```

`base_url: "https://files.example.com"` включает `Secure`-cookie автоматически.
Если прокси передаёт `X-Forwarded-For` — укажите его сеть в `trusted_proxies`,
иначе лимиты будут считаться по адресу прокси.

## Доступ к файлам сервера

По умолчанию смонтирован весь сервер (`/:/host:rw`), а панель показывает то,
что вы в ней подключили. Хотите ограничиться конкретными каталогами — замените
монтирование в `docker-compose.yml`:

```yaml
    volumes:
      - /mnt/media:/host/mnt/media:rw
      - /srv/data:/host/srv/data:rw
      - ./config:/config:ro
      - sunduk_data:/data
```

После этого в панели можно добавить только `/mnt/media` и `/srv/data`.

## Эксплуатация

```bash
docker compose logs -f                 # логи
docker compose restart                 # применить config/config.yml
docker compose down                    # остановить (данные сохраняются)
docker compose down -v                 # остановить и стереть базу/ключ/ссылки

docker compose exec sunduk python tools/reset_admin.py            # вернуть admin/admin
docker compose exec sunduk python tools/reset_admin.py 'пароль'   # задать пароль
docker compose exec -T sunduk python tools/smoke_test.py          # самопроверка
```

Бэкап:

```bash
docker run --rm -v sunduk_data:/data -v "$PWD:/backup" alpine \
    tar czf /backup/sunduk-backup.tgz -C /data .
```

В архиве важны `sunduk.db` (каталоги, пользователи, ссылки) и `secret.key`
(без него не расшифровать токены и пароли ссылок).

## Обновление версии

```bash
docker compose down
# обновите исходники (git pull) или загрузите новый образ
docker compose up -d --build
```

После смены версии зайдите в панель: пароль и каталоги сохраняются в томе
`sunduk_data`, при необходимости сбросьте пароль через `tools/reset_admin.py`.

## Если что-то не работает

| Симптом | Решение |
|---------|---------|
| Панель недоступна с другого компьютера | проверьте `lan_allowlist` и что порт 8080 не блокирует firewall |
| Просят пароль, но он неизвестен | `docker compose exec sunduk python tools/reset_admin.py` |
| «Каталог недоступен на сервере» | папку переименовали/отмонтировали — поправьте путь в панели |
| «каталог не найден на сервере» | путь вне смонтированного `/host` либо не существует |
| Ссылки не открываются извне | `public_ip`/`base_url` и проброс порта 8081 |
| Ошибка монтирования `/` при `docker compose up` | запускать от root (sudo) |
| Контейнер сразу перезапускается | `docker compose logs` — обычно опечатка в `config/config.yml` |
| В логах `data directory /data is unusable: no write permission` | том `/data` остался от старой версии и принадлежит другому пользователю: `docker run --rm -v sunduk_data:/data alpine chown 0:0 /data` |
